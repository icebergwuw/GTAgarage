# 车辆图鉴

日期：2026-09-17

GTA Garage 增加独立图鉴：对照目录告诉玩家收集了多少种车、还缺哪些，并能从卡片入库或跳到停放位置。

## 目标

- 玩家在主界面一眼看到收集进度。
- 打开图鉴后按类别浏览全部目录车型，区分已收集 / 未收集。
- 已收集的车能看到停在哪、跳过去、再入库一台。
- 未收集的车能从图鉴直接放入某个已拥有车库。

## 已锁定的产品规则

- **已收集**：当前库存 `fleet` 里该 `model` 至少有一台。卖光最后一台即未收集。
- **入口**：独立全屏图鉴层。HUD 操作区增加「图鉴」按钮，进度写在按钮上，例如 `图鉴 189/282`。不新增第四个统计数字。
- **「添加车辆」保留**：现有入库弹窗不改成图鉴，两处都写同一份 `fleet`。
- **已收集卡片**：资料 + 停放列表（可跳转）+ 再入库。
- **未收集卡片**：资料 + 入库。未收集也显示名字和照片（压暗），因为图鉴的目的就是对照缺什么。

不做：曾经拥有过的永久图鉴、独立打勾清单、新的 localStorage key、图鉴 URL hash、把「添加车辆」并进图鉴。

## 架构

四个边界清楚的单元。

### 1. `src/lib/collection.ts`

纯函数，只读 `fleet` 和目录。

- `collectedModels(fleet)` → `Set<string>`
- `collectionProgress(fleet, catalog)` → `{ collected, total }`
  - `collected` 是目录中出现在 `collectedModels` 里的数量
  - `total` 是 `catalog.length`（以当时 `vehicles` 为准，不写死 282）
- `classProgress(fleet, catalog, classOrder)` → 每类 `{ class, collected, total }`
- `copiesOf(fleet, model)` → 该车型全部 `StoredVehicle`，保持库存原有顺序

不读写 storage。库存里若出现目录没有的 `model`，现有 `sanitizeFleet` 会丢掉，这里不二次处理。

### 2. HUD

`Hud` 在「购买房产」和「添加车辆」之间加「图鉴」按钮：

- 文案：`图鉴 {collected}/{total}`
- 始终可点（没有已拥有车库时也能打开浏览）
- `onDex` 回调打开图鉴
- 统计区仍是「已拥有 / 载具 / 估值」。「载具」继续表示库存台数，不是去重车型数

按钮跟现有 actions 一样：车库/楼盘面板打开时（`panelOpen`）整行操作区隐藏，关掉面板后才能进图鉴。

### 3. `src/components/DexPanel.tsx`

全屏遮罩图鉴，不塞进已经偏长的 `GaragePanel.tsx`。

负责：类别芯片、状态筛选、图鉴内搜索、网格、空状态、选中车卡。

车卡内的车库/楼层选择复用 `GaragePicker`。车辆照片复用与入库目录相同的 fallback（`/car-fallback.svg`）。若 `VehiclePhoto` 仍只定义在 `GaragePanel.tsx`，抽成小组件给图鉴和入库目录共用。

### 4. `App.tsx` 接线

新状态：

- `dexOpen: boolean`
- `dexModel: string | null`（打开的车卡）

打开图鉴时关掉：入库弹窗、车辆详情、出售确认、车库/楼盘面板。购买房产模式（`shopMode`）下也可以打开图鉴；打开时不退出选址，关掉图鉴后仍停在选址。不改地图搜索，图鉴打开时找车只用图鉴内搜索。

关闭图鉴时清空 `dexModel`。因为打开时已经关掉车库面板，图鉴入库的默认车库是第一处已拥有房产，玩家用 `GaragePicker` 改目标。这和从 HUD 点「添加车辆」且当前没打开车库时的默认目标一致。

## 界面

### 图鉴层

盖住地图的大面板，视觉接近现有 `.modal` + `.catalog`，但占满可用视口。

1. 顶栏：`图鉴 {collected}/{total}`、总进度条、关闭。
2. 类别芯片：`全部` + `classOrder` 中每一类，芯片上 `collected/total`。
3. 状态筛选：`全部` / `已收集` / `未收集`；搜索框匹配厂商、车名、现实原型、内部 id。地图顶栏搜索不搜图鉴。
4. 网格：每种目录车型一张卡。
   - 已收集：正常照片和名字；拥有超过 1 台时角标 `×n`；1 台不标数字。
   - 未收集：同样显示照片和名字，压暗，角标「未收集」。
5. 空状态：一句说明，随筛选变化，例如「这一类已经收集齐了」或「搜不到这个名字」。

默认：类别=全部，状态=全部，搜索为空。切换类别时保留状态筛选和搜索词。

### 车卡

点网格不关图鉴，打开该车型详情：

- 照片、厂商、车名、类别、价格、简介
- 已收集：停放列表，每行显示车库名、楼层、车牌（有则显示）。点一行即跳转
- 底部：`GaragePicker` +「放入车库」
- 没有已拥有车库时，选择器和按钮禁用，提示先购买房产
- 有车库时，默认选中第一处已拥有房产及其第一层，可改

Esc / 点遮罩：先关车卡，再关图鉴。图鉴打开时不打开「添加车辆」。

## 数据流

收集状态只从 `fleet` 派生，重置示例、本地增删改、导出后再导入，图鉴都跟着变。

### 入库

与 `AddVehicle` 同一套 `canPlaceVehicle`。成功则 `uid = sv-${Date.now()}` 追加一条。

与「添加车辆」的差异：图鉴入库后**保持图鉴打开**，不跳到车库、不关图鉴。若这是该车型第一台，进度 +1，卡片立刻变成已收集并出现停放行。同一车型再入库只增加台数和停放行，进度不变。

目标满员：按钮禁用，文案用现有原因（`B1 已满` / `车库已满`）。点击时再检查一次，失败则现有顶部 `notice`，图鉴保持打开。

### 跳转停放位置

关图鉴 → `openGarage(garageId)` → 切到该楼层 → `focusVehicleUid` 聚焦该 `uid`。地图 hash 仍是车库 id。

刷新页面不恢复图鉴。

若跳转时车已被删除：仍打开该车库，不聚焦。若车库已不在 `ownedIds`：只回到地图。

### 卖掉最后一台

车库里「移出车库」后该 `model` 数量为 0：卡片回到未收集，进度 -1。仍剩至少一台：只更新 `×n` 和停放列表。

## 交互与层级

现有 Esc 顺序插入图鉴：

1. 图鉴车卡 → 关车卡
2. 图鉴 → 关图鉴
3. 其余保持现状（入库弹窗 → 车辆详情 → 楼盘单位 → 关车库）

打开图鉴与打开「添加车辆」互斥。

## 错误处理

- 不新做错误页，不用 `alert`
- 入库失败：禁用按钮或 `notice`
- 图片失败：`/car-fallback.svg`
- 目录日后增车：分母变大；已在库存中的新车型自动算已收集

## 验证

项目没有测试框架，第一版不引入。以 `npm run build` 和浏览器回归为准。

必测：

- 示例车队按钮为 `{去重车型数}/{vehicles.length}`，重置后一致
- 图鉴给未收集车入库：进度 +1，卡片已收集，对应车库能看到新车；图鉴仍打开
- 同一车型再入库：进度不变，`×n` 和停放列表增加
- 卖掉该车型最后一台：进度 -1，卡片未收集
- 从停放列表跳转：图鉴关闭，车库打开并聚焦
- 类别、已收集/未收集、搜索叠加正确；空结果有说明
- 没房产时图鉴能看，不能入库
- 图鉴打开时不能叠开「添加车辆」；Esc 先关车卡再关图鉴
- 「添加车辆」加的车会反映到图鉴进度
- 桌面和窄屏都能滚完网格、关掉图鉴

改动后提供本地预览地址，并说明从 HUD「图鉴」按钮进入。
